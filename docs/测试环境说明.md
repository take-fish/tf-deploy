# FishMatrix 测试环境（fishmatrix-test）

> 目标：生产与测试使用**两套独立 MySQL 实例**；Redis / Nacos 仍共享一套，
> 通过 DB1 / `fm-test` namespace 做逻辑隔离。
> 测试流量只写入 `fm-test-mysql` 的 `fm_test_*` 库、Redis DB1 和 Nacos `fm-test`，
> 不接触生产 `fm-mysql` 的 `fm_*` 库、Redis DB0 和 Nacos `fm-prod`。

## 一、隔离模型

| 维度 | 生产（fishmatrix） | 测试（fishmatrix-test） |
|---|---|---|
| 应用编排 | `docker-compose.yml` + `docker-compose.services.yml` | `docker-compose.test.yml` |
| 应用容器名 | `fm-*` | `fm-test-*` |
| 应用网络 | `fishmatrix_default` + `fishmatrix-mw` | `fishmatrix-test_default` + `fishmatrix-mw` |
| MySQL 实例 | `fm-mysql`（宿主 13306） | `fm-test-mysql`（宿主 13307） |
| MySQL 数据卷 | `fishmatrix_mysql-data` | `fishmatrix_test-mysql-data` |
| MySQL 库 | `fm_user` / `fm_chat` / `fm_reader` / `fm_game` / `fm_music` | `fm_test_user` / `fm_test_chat` / `fm_test_reader` / `fm_test_game` / `fm_test_music` |
| 运行时账号 | `fm_<svc>_app`，仅 DML | `fm_test_<svc>_app`，仅 DML |
| 迁移账号 | `fm_<svc>_migrate`，仅本库 DDL | `fm_test_<svc>_migrate`，仅本库 DDL |
| Redis | `fm-redis`（宿主 6379），DB0 | 同一个 `fm-redis`，DB1 |
| Nacos | `fm-nacos`（宿主 8848/9848），namespace `fm-prod`，账号 `fm-app-rw-prod` / `fm-gateway-ro-prod` | 同一个 `fm-nacos`，namespace `fm-test`，账号 `fm-app-rw-test` / `fm-gateway-ro-test` |
| 镜像 tag | `:latest`（master 发布） | `:test`（test 分支 CI 构建，或本地构建） |
| Web / 网关 | 8088 / 8080 | 18088 / 18080 |
| 业务端口 | 8101–8105 | 18101–18105 |

网络关系：

```text
fishmatrix-mw（共享中间件网络）
  ├─ fm-mysql / fm-test-mysql / fm-redis / fm-nacos
  ├─ 生产应用：fm-gateway / fm-web / fm-user / ...
  └─ 测试应用：fm-test-gateway / fm-test-web / fm-test-user / ...

fishmatrix_default（生产应用互访）
  └─ fm-gateway / fm-web / fm-console / fm-user / ...

fishmatrix-test_default（测试应用互访）
  └─ fm-test-* 应用容器
```

- 生产应用通过别名 `mysql:3306` 访问 `fm-mysql`；测试应用通过别名 `mysql-test:3306`
  访问 `fm-test-mysql`，两边不会解析到同一个实例。
- 测试 compose 的应用默认网络中没有 MySQL 服务，只通过 `fishmatrix-mw` 访问测试实例。
- **共享网络上的服务名冲突**：生产与测试应用都接入 `fishmatrix-mw`，而 compose 服务名
  在两边相同（`user`、`chat`……）。Docker DNS 会让 `user` 同时解析到 `fm-user` 和
  `fm-test-user`，静态调用可能串到另一环境。应用间静态地址必须使用环境唯一容器名
  （生产 `fm-*`，测试 `fm-test-*`）；生产 `user` 另有显式别名 `fm-prod-user`。
  当前 chat 默认使用 `fm-test-user:8101`（`TEST_USER_URL` 可覆盖）。
  生产 `web` 的 nginx 上游是 `gateway:8080`，因此生产 `web` 只接 `fishmatrix_default`，
  不接 `mw`；否则会解析到测试网关，注册等请求会写进测试库。测试 `web` 同理只接
  `fishmatrix-test_default`。
- 旧账号 `fm_app`、`fm_test_app` 暂不删除，仅用于回滚；新部署不再使用跨库账号。
- 生产库的日常操作与生产发布不在本文档范围内；生产已于 2026-10-22 完成 B 方案切换。

## 二、数据库账号与迁移模型

每个服务使用两个账号：

| 账号 | 权限 | 使用者 |
|---|---|---|
| `fm_<svc>_app` / `fm_test_<svc>_app` | 本库 `SELECT/INSERT/UPDATE/DELETE` | 业务容器 |
| `fm_<svc>_migrate` / `fm_test_<svc>_migrate` | 本库 DDL + DML | Flyway 迁移任务 |

约束：

- 业务容器固定 `SQL_INIT_MODE=never`、`SPRING_FLYWAY_ENABLED=false`，不建表、不写演示数据。
- 表结构由独立的一次性任务 `db-migrate-*` 用迁移账号执行 Flyway。
- 迁移文件位于各服务 `src/main/resources/db/migration/`：
  - `V1__baseline.sql`：空库直接执行；已有生产库以 `baselineVersion=1` 跳过。
  - 后续变更使用 `V2__...sql`，不得修改已执行的版本文件。
  - reader 的 `R__demo_books.sql` 只在测试镜像路径 `db/testdata` 中，生产不加载。
- 启动副作用已关闭：
  - `AdminSeeder` 由 `fm.user.admin.seed-enabled` 控制，生产默认 `false`；
    测试 compose 显式设为 `true`，重启 user 时会补齐测试管理员。
  - 聊天默认群组由 `V1__baseline.sql` 插入，不再在运行时写库。
  - reader 演示书籍由测试 seed 提供，不再随业务容器启动写入。


`build-test-local.sh` 以生产 `:latest` 镜像为基底覆盖 `app.jar`，不拉取基础镜像；

日志 `D:\develop\fm-auto-update-test.log`。

### 新增数据库迁移

1. 在对应服务新增 `V2__xxx.sql`，本地 `mvn -B test` 验证。
2. 构建并部署：
   ```bash
   bash scripts/build-test-local.sh user
   ```
   脚本会先运行 `db-migrate-user`，成功后再重建 `user`。
3. 检查 `flyway_schema_history` 新增记录且 `success=1`。

### 自动更新

`auto-update-test.sh` 只操作测试应用镜像。拉取到新的 user/chat/reader/game 镜像后，
会先用 `.fm-test-migrated-images` 记录判断镜像是否变化；变化时先执行
`db-migrate-user/chat/reader/game`，再逐个重建业务容器。迁移失败时脚本退出，不继续重建应用。

> **当前网络限制**：集中机到 ghcr 镜像层下载速度约 20 KB/s。
> `auto-update-test.sh` 默认拉取超时 180 秒（`TEST_PULL_TIMEOUT` 可调），
> 计划任务 `FishMatrix-auto-update-test` 目前处于禁用状态：
>
> ```bat
> schtasks /Change /TN "FishMatrix-auto-update-test" /ENABLE
> ```

## 六、备份、恢复与重建

### 备份

```bash
cd D:\code\cloud-take-fish\tf-deploy

bash scripts/backup-mysql.sh prod   # fm-mysql -> backups/prod-mysql-*.sql.gz
```

- 密码通过容器内 `MYSQL_PWD` 传入，不出现在宿主机命令行。

- 备份后自动做 gzip 完整性校验。

恢复测试库：

```bash

  docker exec -i -e MYSQL_PWD="$TEST_MYSQL_ROOT_PASSWORD" fm-test-mysql mysql -uroot
```

### 重建测试库

`reset-test-db.sh` 只允许操作 `fm-test-mysql`，并做三重保护：
容器名必须是 `fm-test-mysql`、数据目录必须挂载 `fishmatrix_test-mysql-data`、
必须传 `--yes` 且输入确认短语。

```bash
cd D:\code\cloud-take-fish\tf-deploy
bash scripts/backup-mysql.sh test
bash scripts/reset-test-db.sh --yes
# 交互输入：RESET fm-test-mysql
# 非交互：FM_TEST_RESET_CONFIRM="RESET fm-test-mysql" bash scripts/reset-test-db.sh --yes

docker compose -f docker-compose.test.yml up --force-recreate \
  db-migrate-user db-migrate-chat db-migrate-reader db-migrate-game
docker compose -f docker-compose.test.yml up -d --no-deps --force-recreate user chat reader game
```

重置后 user 重启会由 `AdminSeeder` 重建测试管理员；chat 默认群组与 reader 演示数据
由迁移/seed 重建。账号本身不会被删除。

> 不要执行 `docker compose -f docker-compose.middleware.yml down -v`，除非确认要删除
> `fishmatrix_mysql-data` / `fishmatrix_test-mysql-data` / `fishmatrix_redis-data` /
> `fishmatrix_nacos-data`。

### 功能检查清单

1. 两个账号登录后同时打开 `/chat`，双方侧栏“在线进程”可见对方。
2. 同一群组内互发消息实时可见；切群后历史仍在，向上翻页游标正确。

7. token 失效或退出登录后，聊天连接停止重连并跳回 `/login?redirect=/chat`。

## 八点五、统一权限、Reader/Music 双库与访问申请

### 身份与密钥

- 网关校验用户中台 token 后，向业务服务注入 HMAC 签名身份头
  （`X-FM-User-Id/Username/Nickname/Role/Roles/Permissions/Exp/Signature`）。
- `FM_IDENTITY_SECRET` 与 `TEST_FM_IDENTITY_SECRET` 必须不同；`scripts/ensure-identity-secrets.sh`
  只补齐空值、不打印内容。测试栈容器使用 `TEST_FM_IDENTITY_SECRET`。
- 业务服务 `fm.auth.user-service-url` 指向 `fm-test-user:8101`，仅供直连调试时的 Bearer 回退；
  网关正常链路不依赖该调用。
- 用户中台自身 `fm.auth.enabled=false`，避免自调用。

### 文件与卷

- reader/music 的原文/音频落测试命名卷：`fishmatrix-test_reader-test-files`、
  `fishmatrix-test_music-test-files`，容器内路径 `/app/data/files`。
- 数据库只存 `storage_key`、大小、MIME 与 SHA-256；权限判断只看库表，不看路径。
- music 的 `/stream` 支持单段 `Range`，返回 206；多段返回 416。

### 重建与迁移

```bash
cd D:\code\cloud-take-fish\tf-deploy
bash scripts/build-test-local.sh user reader music gateway web
# 脚本会先执行 db-migrate-user/reader/music，再重建对应容器
```

### 端到端验证

```bash
cd D:\code\cloud-take-fish\tf-deploy
python scripts/verify-unified-platform.py
```

脚本只访问测试栈（`18080`），从 `.env` 读取测试管理员密码，全程不输出 token/密码。覆盖：

1. 管理员登录、`/auth/me`、权限目录；普通用户读取权限目录 403；
2. 匿名 401、直连服务伪造签名头 401、Bearer 回退 200；
3. 注册 → 审批 → 普通用户默认权限；
4. Reader 私有书上传、非 owner 404、分享预览、申请 → 同意 → 阅读 → 收回 → 再次 404；
5. 第二用户越权访问/删除 404，个人书单隔离；

## 九、Nacos 分级账号与网关动态路由

### 9.1 账号模型

| 账号 | 角色权限 | 使用者 |
|---|---|---|
| `fm-gateway-ro-prod` / `fm-gateway-ro-test` | 目标 namespace `r` | 生产 / 测试网关 |
| `fm-app-rw-prod` / `fm-app-rw-test` | 目标 namespace `r` + `w` | 生产 / 测试业务服务 |
| `fm-config-admin` | `fm-prod` / `fm-test` 的 `r` + `w` | 发布配置的运维脚本 |

Nacos 2.5.1 的权限 action 按操作精确匹配，**读写账号必须分别授予 `r` 和 `w`**；
只授予 `rw` 时读取正常、配置发布会被 403 拒绝。权限粒度为 namespace 级。

`nacos-init` / `init-test-nacos.sh` 仍使用管理员账号发布配置；应用容器和网关不再注入管理员密码。

### 9.2 初始化与验证

```bash
cd D:\code\cloud-take-fish\tf-deploy

# 生成缺失的分级账号密码，写入 .env（不打印）
bash scripts/ensure-nacos-secrets.sh

# 幂等创建用户/角色/权限，并执行只读、写权限、服务注册探针
bash scripts/init-nacos-accounts.sh
```

脚本最后应输出：

```text
验证通过：fm-gateway-ro-test 可读取 fm-test 配置
验证通过：fm-gateway-ro-test 无配置写权限
验证通过：fm-app-rw-test 可注册服务实例
验证通过：fm-config-admin 可发布配置
```

探针只注册临时实例（`ephemeral=true`）。持久实例依赖 Raft，单机 Nacos 若
`naming_persistent_service_v2` 无 Leader 会注册失败；Spring Cloud 默认使用临时实例，不受影响。
