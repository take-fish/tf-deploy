# FishMatrix 测试环境（fishmatrix-test）

> 目标：用同一套共享中间件（MySQL / Redis / Nacos）承接测试流量，通过**逻辑隔离**做到与生产互不影响；
> 测试栈只额外运行业务容器，不拉取新的中间件镜像。

## 一、隔离模型

| 维度 | 生产（fishmatrix） | 测试（fishmatrix-test） |
|---|---|---|
| 编排文件 | `docker-compose.yml` + `docker-compose.services.yml` | `docker-compose.test.yml` |
| 容器名 | `fm-*` | `fm-test-*` |
| 网络 | `fishmatrix_default` | `fishmatrix-test_default`（独立） |
| MySQL | `fm_user` / `fm_chat` / `fm_reader` / `fm_game` / `fm_music` | `fm_test_user` / `fm_test_chat` / `fm_test_reader` / `fm_test_game` / `fm_test_music` |
| Redis | DB0 | DB1 |
| Nacos | namespace `fm-prod` | namespace `fm-test` |
| 镜像 tag | `:latest`（master 发布） | `:test`（test 分支 CI 构建） |
| Web / 网关 | 8088 / 8080 | 18088 / 18080 |
| 业务端口 | 8101–8105 | 18101–18105 |

测试容器不加入生产 compose 网络，容器内通过 `host.docker.internal:<port>` 访问集中机已发布的
MySQL(3306) / Redis(6379) / Nacos(8848)。Linux 主机由 `extra_hosts: host.docker.internal:host-gateway` 提供。

> 说明：集中机 Windows 防火墙未对局域网开放 3306/6379/8848，因此测试栈不使用 LAN IP，
> 改用 `host.docker.internal`（仍走集中机已发布端口，不加入生产网络）。如需改用固定地址，
> 设置 `.env` 的 `TEST_MIDDLEWARE_HOST=<IP或域名>` 即可。

## 二、Nacos 配置

- 每个服务一个 dataId：`tf-user.yaml` / `tf-chat.yaml` / `tf-reader.yaml` / `tf-game.yaml` / `tf-music.yaml`，group=`FM`
- 模板在 `deploy/nacos/{prod,test}/`，由 `scripts/init-nacos.sh` 幂等发布
- 服务端启动参数（Nacos 地址 / namespace / 账号密码）仍由 compose 环境变量注入：
  - 生产：`SPRING_PROFILES_ACTIVE=nacos`、`NACOS_NAMESPACE=fm-prod`
  - 测试：`SPRING_PROFILES_ACTIVE=nacos`、`NACOS_NAMESPACE=fm-test`
- 服务通过 `application-nacos.yml` 的 `spring.config.import` 拉取配置；本地运行与单元测试不激活该 profile，不依赖 Nacos
- MySQL 密码在配置中使用 `${MYSQL_APP_PASSWORD}` 占位，由容器环境变量注入，不写入 Nacos

## 三、首次部署

```bash
cd D:\code\cloud-take-fish\tf-deploy

# 1) 初始化共享资源（幂等）
bash scripts/init-db.sh        # fm_test_* 库
bash scripts/init-nacos.sh     # fm-prod / fm-test namespace + 配置

# 2) 构建并推送测试镜像
#    push test 分支后由各仓 .github/workflows/test-image.yml 自动完成

# 3) 拉起测试栈
docker compose -f docker-compose.test.yml up -d
docker compose -f docker-compose.test.yml ps

# 4) 验证
curl http://localhost:18080/healthz
curl http://localhost:18088/
curl http://localhost:18101/actuator/health
```

## 四、自动部署

```
push test → GitHub Actions（test-image.yml）→ ghcr :test
                                   │
[集中机] FishMatrix-auto-update-test（每 2 分钟）
   └─ scripts/auto-update-test.sh：compose pull → 重建有变化的测试容器
```

Windows 计划任务封装脚本位于 `D:\develop\fm-auto-update-test.cmd`，日志 `D:\develop\fm-auto-update-test.log`。

## 五、验证隔离是否生效

```bash
# 1) 测试库表结构与数据独立
docker exec -e MYSQL_PWD=<root密码> fm-mysql mysql -uroot -e "SHOW DATABASES LIKE 'fm_test%';"

# 2) Redis DB1 有测试键，DB0 不受影响
docker exec fm-redis redis-cli -n 1 KEYS 'tf:*' | head
docker exec fm-redis redis-cli -n 0 KEYS 'tf:*' | head

# 3) Nacos 实例注册在 fm-test
curl "http://localhost:8848/nacos/v1/ns/instance/list?serviceName=tf-user&namespaceId=fm-test"
curl "http://localhost:8848/nacos/v1/ns/instance/list?serviceName=tf-user&namespaceId=fm-prod"
```

## 六、常用命令

```bash
# 测试栈
docker compose -f docker-compose.test.yml up -d
docker compose -f docker-compose.test.yml logs -f user chat reader game music
docker compose -f docker-compose.test.yml down          # 只停测试容器，不影响中间件与生产
bash scripts/auto-update-test.sh

# 配置更新（修改 deploy/nacos 模板后）
bash scripts/init-nacos.sh
docker compose -f docker-compose.test.yml up -d --no-deps user chat reader game music

# Nacos 鉴权开启后，脚本自动读取 .env 的 NACOS_ADMIN_PASSWORD
NACOS_PASSWORD=*** bash scripts/init-nacos.sh
```
