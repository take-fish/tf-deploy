# FishMatrix 测试环境（fishmatrix-test）

> 目标：中间件只维护一套（`docker-compose.middleware.yml`），生产与测试应用各自运行；
> 测试流量打到测试实例（`fm_test_*` 库 / Redis DB1 / Nacos `fm-test`），生产流量打到生产实例
> （`fm_*` 库 / Redis DB0 / Nacos `fm-prod`）。

## 一、隔离模型

| 维度 | 生产（fishmatrix） | 测试（fishmatrix-test） |
|---|---|---|
| 应用编排 | `docker-compose.yml` + `docker-compose.services.yml` | `docker-compose.test.yml` |
| 应用容器名 | `fm-*` | `fm-test-*` |
| 应用网络 | `fishmatrix_default` + `fishmatrix-mw` | `fishmatrix-test_default` + `fishmatrix-mw` |
| 中间件编排 | `docker-compose.middleware.yml`（唯一一套） | 同左 |
| 中间件网络 | `fishmatrix-mw`（生产应用接入） | `fishmatrix-mw` |
| MySQL | `fm-mysql`（宿主 13306；局域网 `10.28.13.214:3306` 转发到 13306） | 同一个 `fm-mysql` |
| Redis | `fm-redis`（宿主 6379） | 同一个 `fm-redis` |
| Nacos | `fm-nacos`（宿主 8848/9848） | 同一个 `fm-nacos` |
| MySQL 库 | `fm_user` / `fm_chat` / `fm_reader` / `fm_game` / `fm_music` | `fm_test_user` / `fm_test_chat` / `fm_test_reader` / `fm_test_game` / `fm_test_music` |
| MySQL 账号 | `fm_app`（只授权生产库） | `fm_test_app`（只授权 `fm_test_%`） |
| Redis | DB0 | DB1 |
| Nacos | namespace `fm-prod` | namespace `fm-test` |
| 数据卷 | `fishmatrix_mysql-data` / `fishmatrix_redis-data` / `fishmatrix_nacos-data` | 同左（共享物理卷） |
| 镜像 tag | `:latest`（master 发布） | `:test`（test 分支 CI 构建，或本地构建） |
| Web / 网关 | 8088 / 8080 | 18088 / 18080 |
| 业务端口 | 8101–8105 | 18101–18105 |

网络关系：

```text
fishmatrix_default（生产应用互访）
  └─ fm-gateway / fm-web / fm-console / fm-user / fm-chat / ...

fishmatrix-mw（共享中间件）
  └─ fm-mysql / fm-redis / fm-nacos（同一批容器）
     fm-gateway / fm-web / fm-console / fm-user / fm-chat / ...（生产应用）
     fm-test-gateway / fm-test-web / fm-test-user / fm-test-chat / ...（测试应用）

fishmatrix-test_default（测试应用互访）
  └─ fm-test-* 应用容器
```

- 中间件只启动一套，容器名仍是 `fm-mysql` / `fm-redis` / `fm-nacos`，只接入 `fishmatrix-mw`。
  存量运行容器可能仍保留切换前接入的 `fishmatrix_default`，重建中间件后自动移除；
  测试应用未接入该网络，不影响隔离。
- 生产应用同时接入 `fishmatrix_default`（应用互访）和 `fishmatrix-mw`（访问中间件）。
- 测试应用同时接入 `fishmatrix-test_default`（应用互访）和 `fishmatrix-mw`（访问中间件）。
- 两边都通过 compose 服务名 `mysql` / `redis` / `nacos:8848` 访问共享中间件；
  测试 compose 中没有 `mysql` / `redis` / `nacos` 服务，因此不会解析到应用容器。
- 新机器可以先启动 `docker-compose.middleware.yml`（创建 `fishmatrix-mw`），再启动应用编排。
- 测试账号 `fm_test_app` 只授权 `fm_test_%` 库；测试 Nacos 配置只写入 `fm-test` 命名空间。

## 二、中间件初始化

### 1. 测试密钥

首次部署执行：

```bash
cd D:\code\cloud-take-fish\tf-deploy
bash scripts/ensure-test-secrets.sh
```

脚本只在缺失/为空时生成 `TEST_MYSQL_APP_PASSWORD`，写入 `.env`（权限 600），全程不打印值。
测试 Nacos 复用生产 Nacos 管理员（`NACOS_ADMIN_PASSWORD`），不再维护独立测试管理员。

### 2. 启动共享中间件

```bash
docker compose -f docker-compose.middleware.yml up -d mysql redis nacos
docker compose -f docker-compose.middleware.yml ps
```

`fm-mysql` 首次创建数据卷时会执行 `scripts/mysql-middleware-init.sh`，
同时创建生产库/账号与测试库/账号（测试密码为空时跳过测试账号，可稍后用脚本补齐）。

已存在数据卷时，增量初始化：

```bash
bash scripts/init-db.sh       # 生产库 + fm_app
bash scripts/init-test-db.sh  # fm_test_* 库 + fm_test_app
```

`init-test-db.sh` 还会撤销旧方案中 `fm_app` 对 `fm_test_%` 的授权（如果存在）。

> 本机 `localhost:3306` 是原生 MySQL，不是共享中间件。其他电脑访问共享 MySQL 使用
> `10.28.13.214:3306`：Windows 端口转发到 Docker 的 `13306`；生产/测试按库名与账号区分。
> 转发规则已加入 `D:\develop\restore-lan-ports.ps1`，重跑该脚本不会丢失。

### 3. Nacos

共享 Nacos 使用 `fishmatrix_nacos-data` 卷，生产/测试命名空间持久化在其中。

- 生产/测试全部配置：`bash scripts/init-nacos.sh`（创建 `fm-prod`、`fm-test` 并发布两份配置）。
- 只发布测试配置：`docker compose -f docker-compose.test.yml up -d --force-recreate nacos-init`。

`nacos-init` 是测试 compose 中的一次性容器，在共享 Nacos 健康后：

1. 使用 `NACOS_ADMIN_PASSWORD` 登录；
2. 创建/复用 namespace `fm-test`；
3. 把 `deploy/nacos/test/tf-*.yaml` 发布到 group `FM`。

应用服务通过 `depends_on` 等待 `middleware-ready` 与 `nacos-init` 成功完成后再启动。

> `nacos-init` 退出即完成，普通 `docker compose ps` 不显示；
> 使用 `docker compose ps -a` 或 `docker logs fm-test-nacos-init` 查看。

## 三、首次部署测试应用

```bash
cd D:\code\cloud-take-fish\tf-deploy

# 1) 测试密钥（首次）
bash scripts/ensure-test-secrets.sh

# 2) 共享中间件
docker compose -f docker-compose.middleware.yml up -d mysql redis nacos

# 3) 测试库与 Nacos 配置
bash scripts/init-test-db.sh

# 4) 测试应用（会自动运行 middleware-ready / nacos-init）
docker compose -f docker-compose.test.yml up -d
docker compose -f docker-compose.test.yml ps -a

# 5) 验证
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:18080/healthz
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:18088/
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:18080/api/v1/reader/books
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:18080/api/v1/chat/groups   # 未带 token 应为 401
```

首次启动共享 MySQL、Nacos 需要几十秒；`middleware-ready` 会等待端口可达。

## 四、自动部署与网络限制

```text
push test → GitHub Actions（test-image.yml）→ ghcr :test
                                   │
[集中机] FishMatrix-auto-update-test（每 2 分钟）
   └─ scripts/auto-update-test.sh：compose pull → 重建有变化的测试应用容器
```

`auto-update-test.sh` 只操作 `gateway web user chat reader game music`，
不会启动或重建共享中间件，也不触碰生产应用。

> **当前网络限制**：集中机到 ghcr 镜像层的下载速度实测约 20 KB/s，单个 Java 镜像的
> 业务层约 52 MB，5 个服务需数小时。`auto-update-test.sh` 已加拉取超时（默认 180 秒，
> `TEST_PULL_TIMEOUT` 可调），避免永久占用锁；计划任务 `FishMatrix-auto-update-test`
> 目前处于**禁用**状态，待网络恢复后启用：
>
> ```bat
> schtasks /Change /TN "FishMatrix-auto-update-test" /ENABLE
> ```

网络受限期间使用本地构建通道：

```bash
bash scripts/build-test-local.sh                 # 全部 Java 服务
bash scripts/build-test-local.sh user chat       # 仅指定服务
bash scripts/build-test-local.sh web user        # 前端（Node 24 + 本地 nginx 基底）+ user
```

该脚本以生产 `:latest` 镜像为基底覆盖 `app.jar`，不拉取基础镜像；只重建指定测试服务，
不触碰生产容器。Windows 计划任务封装脚本位于 `D:\develop\fm-auto-update-test.cmd`，
日志 `D:\develop\fm-auto-update-test.log`。

## 五、验证隔离是否生效

```bash
# 1) 测试应用解析到共享中间件
docker exec fm-test-chat getent hosts mysql redis nacos

# 2) 测试应用与生产应用不在同一默认网络；只共享 fishmatrix-mw
docker inspect fm-test-chat --format '{{json .NetworkSettings.Networks}}'
docker inspect fm-chat --format '{{json .NetworkSettings.Networks}}'

# 3) 测试账号只能看到/操作 fm_test_* 库
docker exec fm-mysql sh -c \
  'MYSQL_PWD=$MYSQL_ROOT_PASSWORD mysql -uroot -N -e \
   "SHOW GRANTS FOR '\''fm_test_app'\''@'\''%'\'';"'

# 4) 测试库表结构与数据独立
docker exec fm-mysql sh -c \
  'MYSQL_PWD=$MYSQL_ROOT_PASSWORD mysql -uroot -e "SHOW TABLES FROM fm_test_reader;"'

# 5) 测试 Redis 写入 DB1，生产仍使用 DB0
docker exec fm-redis redis-cli -n 1 --scan --pattern 'tf:*' | head
docker exec fm-redis redis-cli -n 0 --scan --pattern 'tf:*' | head

# 6) Nacos 实例注册在共享 Nacos 的 fm-test namespace
docker exec fm-nacos sh -c \
  'curl -s "http://127.0.0.1:8848/nacos/v1/ns/instance/list?serviceName=tf-user&namespaceId=fm-test"'
```

确认测试应用网络列表包含 `fishmatrix-mw` 和 `fishmatrix-test_default`，
生产应用网络列表包含 `fishmatrix-mw` 和 `fishmatrix_default`；两边都不再有独立的测试中间件容器。

## 六、常用命令

```bash
# 共享中间件
docker compose -f docker-compose.middleware.yml up -d
docker compose -f docker-compose.middleware.yml ps
docker compose -f docker-compose.middleware.yml logs -f mysql redis nacos

# 测试应用
docker compose -f docker-compose.test.yml up -d
docker compose -f docker-compose.test.yml ps -a
docker compose -f docker-compose.test.yml logs -f user chat reader game music
docker compose -f docker-compose.test.yml down          # 停止测试应用，保留数据卷
bash scripts/auto-update-test.sh
bash scripts/build-test-local.sh

# 仅重建测试配置
docker compose -f docker-compose.test.yml up -d --force-recreate nacos-init
docker compose -f docker-compose.test.yml up -d --no-deps --force-recreate user chat reader game music

# 初始化/修复测试库
bash scripts/init-test-db.sh
```

> 不要执行 `docker compose -f docker-compose.middleware.yml down -v`，除非确认要删除
> `fishmatrix_mysql-data` / `fishmatrix_redis-data` / `fishmatrix_nacos-data`，
> 这会同时删除生产与测试数据。

## 七、登录入口与用户中台

测试应用的登录链路：

| 入口 | 测试地址 |
|---|---|
| 登录页 / 工作台 | `http://localhost:18088`（未登录访问任意路由都会跳到 `/login`） |
| 用户中台（直连） | `http://localhost:18101/admin/` |
| 用户中台（经 Web/网关） | `http://localhost:18088/api/v1/user/admin/index.html` |

- 管理员用户名默认 `admin`；生产密码在 `.env` 的 `USER_ADMIN_PASSWORD`，测试密码在
  `TEST_USER_ADMIN_PASSWORD`，由 `scripts/ensure-user-admin-secrets.sh` 生成，互不复用。
- 新用户注册后状态为 `PENDING`，登录返回 403 `PENDING_APPROVAL`；管理员在用户中台批准后
  变为 `ACTIVE` 才能进入工作台。
- 账号数据只落在共享 `fm-mysql` 的 `fm_test_user.user_account`；会话 token 存
  共享 `fm-redis` DB1 的 `fm:user:session:<sha256(token)>`，TTL 7 天并随访问续期。
- 管理员密码生成或修改后需重建测试 user 容器：
  `docker compose -f docker-compose.test.yml up -d --no-deps --force-recreate user`。

验证清单（人工）：

1. 打开 `http://localhost:18088/reader`，应落到登录页并显示“你认识我吗？”。
2. 点“不认识”注册 → 显示“等待通过中”。
3. 用户中台登录 → 批准该用户 → 登录页“认识”两问登录 → 回到 `/reader`。
4. 退出登录后再次访问受保护路由，应重新要求登录。

## 八、聊天模块（鉴权、持久化与实时通道）

### 配置与网络

- `tf-chat.yaml`（`fm-test`）通过 `TF_USER_URL=http://user:8101` 访问同一测试网络内的用户服务，
  校验 `Authorization: Bearer <token>`。
- 消息落在共享 `fm-mysql` 的 `fm_test_chat.chat_message` / `chat_group` /
  `chat_read_state`，启动时由 `spring.sql.init`（`SQL_INIT_MODE=always`）幂等建表。
- 实时状态在共享 `fm-redis` DB1：`tf:chat:online*`、`tf:chat:presence:*`、
  `tf:chat:offline:*`、`tf:chat:auth:*`、`tf:chat:ws-ticket:*`、`tf:chat:rate:*`、`tf:chat:events`。
- nginx / 网关继续使用 `/api/` 与 `/ws/` 前缀；WS 握手参数为 `?ticket=`。

### 重建测试服务

```bash
cd D:\code\cloud-take-fish\tf-deploy
# 若修改了 deploy/nacos/test/tf-chat.yaml
docker compose -f docker-compose.test.yml up -d --force-recreate nacos-init
bash scripts/build-test-local.sh chat web  # 本地构建叠加测试镜像
docker compose -f docker-compose.test.yml up -d --no-deps --force-recreate chat web
```

> 只重建 `chat` / `web`，不影响生产容器与共享中间件。

### 接口验证

```bash
# 1) 未带 token -> 401；伪造 token -> 401
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:18080/api/v1/chat/groups
curl -s -o /dev/null -w '%{http_code}\n' \
  -H 'Authorization: Bearer fake-token' http://localhost:18080/api/v1/chat/groups

# 2) 登录后拿 token（在用户中台批准账号后执行）
#    curl -s -X POST http://localhost:18080/api/v1/user/auth/login \
#      -H 'Content-Type: application/json' -d '{"username":"...","password":"..."}'
#    TOKEN=<返回的 token>

# 3) 群组 / 历史 / 未读 / 一次性 ticket
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:18080/api/v1/chat/groups
curl -s -H "Authorization: Bearer $TOKEN" \
  'http://localhost:18080/api/v1/chat/groups/dev-group/history?limit=20'
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:18080/api/v1/chat/unread
curl -s -X POST -H "Authorization: Bearer $TOKEN" http://localhost:18080/api/v1/chat/ws-ticket
```

WebSocket（需安装 `websocat` 或使用浏览器控制台）：

```bash
# ticket 只能使用一次；重复使用会被拒绝
websocat "ws://localhost:18080/ws/chat?ticket=$TICKET"
# 无 ticket 或被消费后应握手失败
websocat "ws://localhost:18080/ws/chat"
```

### 数据落库确认

```bash
docker exec fm-mysql sh -c \
  'MYSQL_PWD=$MYSQL_ROOT_PASSWORD mysql -uroot -e \
   "SELECT seq, conversation_id, from_user_id, LEFT(content,20), created_at \
    FROM fm_test_chat.chat_message ORDER BY seq DESC LIMIT 5; \
    SELECT * FROM fm_test_chat.chat_read_state LIMIT 5;"'

docker exec fm-redis redis-cli -n 1 --scan --pattern 'tf:chat:*' | head
```

确认生产 `fm-mysql.fm_chat` 与 `fm-redis` DB0 不会被测试流量写入。

### 功能检查清单

1. 两个账号登录后同时打开 `/chat`，双方侧栏“在线进程”可见对方。
2. 同一群组内互发消息实时可见；切群后历史仍在，向上翻页游标正确。
3. `grep <关键字>` 能命中历史；`who` 展示全局在线；`recall #<短ID>` 撤回自己 2 分钟内的消息，对方终端显示“该消息已撤回”。
4. 私聊接收方离线时发送，重连后收到补发；重复 `clientMsgId` 不产生第二条消息。
5. 打开会话或 `tail -f` 后群组未读徽标归零；刷新页面未读与历史一致。
6. 连续快速发送超过 20 条/10 秒出现 `RATE_LIMITED`/429；含 ANSI 控制字符的内容被清理。
7. token 失效或退出登录后，聊天连接停止重连并跳回 `/login?redirect=/chat`。
