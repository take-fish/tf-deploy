# 自动更新说明（集中机）

## 机制

合 master → 各服务仓 Release 工作流自动构建并推送 ghcr 镜像（`:vX.Y.Z` + `:latest`）→ 集中机上的定时器每 2 分钟轮询 ghcr，发现 `:latest` 指向新镜像后自动 pull 并重建对应容器。端到端约 5~10 分钟（含 CI 与构建时间）。

```
[开发者] 合 master
   └─ GitHub Actions：构建 → 推 ghcr (:vX.Y.Z, :latest) → 建 tag + Release
                                  │
[集中机]  fm-auto-update.timer（每 2 分钟）
   └─ scripts/auto-update.sh：compose pull 应用服务 → 重建有更新的容器
```

集中机只需**出站**网络（拉取 ghcr 走 HTTPS），无需任何入站端口。

## 覆盖范围与取舍

- 同时加载 `docker-compose.yml` 与 `docker-compose.services.yml`
- 自动更新 `scripts/auto-update.sh` 的 `APP_SERVICES`：
  `gateway console web user chat reader game music`
- MySQL / Redis / ES / Nacos 等基础中间件**刻意不自动更新**：这些镜像 tag 可变，无人值守升级有数据风险，升级走人工评估
- compose 文件本身的变更（新增服务、改环境变量）不会自动下发——运行时版本以 ghcr `:latest` 为准；编排变更仍需人工 `git pull` + `docker compose ... up -d`
- 想固定版本停止跟随：在 `.env` 中把对应 `TF_*_TAG`（如 `TF_GATEWAY_TAG`、`TF_WEB_TAG`）改为具体版本号，自动更新即停在该 tag

## 安装（集中机，一次性）

```bash
git clone git@github.com:take-fish/tf-deploy.git
cd tf-deploy
cp .env.example .env
docker compose up -d
bash scripts/init-db.sh          # 初始化 fm_* 库与 fm_app 授权
docker compose -f docker-compose.yml -f docker-compose.services.yml up -d
sudo docker login ghcr.io        # 私有镜像，PAT 需 read:packages
sudo bash scripts/install-auto-update.sh
```

安装脚本会把 `deploy/systemd/` 下的模板渲染实际仓库路径后装入 `/etc/systemd/system/`，并 `enable --now` 定时器。定时器以 root 运行，因此 ghcr 凭据要登录在 root 下（如上）。

## 常用命令

```bash
systemctl list-timers fm-auto-update.timer          # 查看下次触发时间
journalctl -u fm-auto-update.service -f             # 实时查看更新日志
sudo systemctl start fm-auto-update.service         # 手动触发一轮
sudo bash scripts/auto-update.sh                    # 或直接跑脚本
sudo systemctl disable --now fm-auto-update.timer   # 暂停自动更新
```

## 无 systemd 环境的 cron / Windows 备选

```cron
*/2 * * * * /bin/bash /opt/tf-deploy/scripts/auto-update.sh >> /var/log/fm-auto-update.log 2>&1
```

Windows 集中机使用计划任务 `FishMatrix-auto-update` 调用同一脚本（静默包装脚本见本机 `D:\develop\fm-auto-update.cmd`）。

（脚本自带 flock 防重叠，cron 与 systemd 可混用）

## 新增业务服务时

1. 服务编排进 `docker-compose.services.yml`（常用服务放 `docker-compose.yml`）
2. 把服务名追加到 `scripts/auto-update.sh` 的 `APP_SERVICES`
3. 合 master 后，集中机先人工 `git pull` + `docker compose ... up -d` 一次（让新编排生效），之后的镜像更新即由定时器接管

## 排障

- **拉取失败**：确认运行用户已 `docker login ghcr.io`（systemd 以 root 运行）；集中机只需出站 HTTPS，无需入站
- **一直"已是最新"但期望有新版本**：确认对应仓库的 Actions 已推 `:latest`；确认 `.env` 里对应 `TF_*_TAG` 未被固定为旧版本
- **更新后服务异常**：`docker compose ... logs <服务>` 查看；镜像若走 `:latest`，回退可临时固定 `TF_*_TAG=vX.Y.Z`
- **Windows / WSL 集中机**：systemd 方案不适用，改用计划任务或 WSL 内的 cron 调用同一脚本
