# FishMatrix 服务分机部署与发版手册

> 适用范围：把 `tf-user`、`tf-reader`、`tf-game`、`tf-music`、`tf-console` 中的一个或多个服务从集中机拆出，在**分机**（另一台电脑）上运行；MySQL、Redis、Nacos、网关、Web 仍留在集中机。
> 本文所有 `<分机IP>` 都替换成分机的**局域网 IP**（例如 `192.168.1.23`），不要填 `127.0.0.1`、WSL/Docker 的 `172.x` 或公网 IP。
> 集中机地址按现有配置写为 `10.28.13.214`，如实际不同请全局替换。

---

## 0. 结论先看

拆分**不改业务代码，只改部署拓扑**，但有几个共同前提：

1. **注册 IP 必须是分机局域网 IP**：容器默认把自己的 `172.x` 容器 IP 注册到 Nacos，集中机网关访问不到。必须用 `SPRING_CLOUD_NACOS_DISCOVERY_IP` 覆盖。
2. **Java 服务的身份签名密钥必须与网关一致**：`FM_IDENTITY_SECRET` 不一致，网关转发过来的每个请求都会 401。密钥只能线下安全传递。
3. **文件类服务要搬数据卷**：`reader`、`music` 的原文/音频在命名卷里，数据库只存 `storage_key`；卷不搬，已有内容会缺失。
4. **同一时间只保留一个实例**：旧实例没停就启动新实例，网关会在两个实例间轮询，读到旧卷、旧版本，行为随机。
5. **迁移统一由集中机执行**：分机只跑业务容器，不跑 Flyway。否则同一数据库会出现两个迁移版本。

服务差异很大，拆之前先看第 1 节矩阵，尤其是 `user` 和 `console` 的特殊性。

## 1. 适用服务与差异矩阵

| 服务 | 镜像 | 端口 | 数据库 / 运行时账号 | 数据卷 | Nacos 服务名 | 网关路由 | Redis | Flyway 迁移 Job | 拆分风险 |
|---|---|---|---|---|---|---|---|---|---|
| `user` | `tf-user` | `8101` | `fm_user` / `fm_user_app` | 无 | `tf-user` | `/api/v1/user` | 必须（会话） | `migrate-user` | **高**：全站身份来源 |
| `reader` | `tf-reader` | `8103` | `fm_reader` / `fm_reader_app` | `fishmatrix_reader-files` | `tf-reader` | `/api/v1/reader` | 健康检查用 | `migrate-reader` | 中：原文卷 |
| `game` | `tf-game` | `8104` | `fm_game` / `fm_game_app` | 无 | `tf-game` | `/api/v1/game` | **必须（排行榜）** | 无（当前无表） | 中：强依赖 Redis |
| `music` | `tf-music` | `8105` | `fm_music` / `fm_music_app` | `fishmatrix_music-files` | `tf-music` | `/api/v1/music` | 健康检查用 | `migrate-music` | 中：音频卷、大文件 |
| `console` | `tf-console` | `8301` | 无 | 无 | **不注册** | **不经网关** | 不需要 | 无 | **特殊**：浏览器直连 |

关键差异：

- **`user` 是所有服务与网关的身份事实来源**。它一旦在分机上不可达，全站登录、会话校验、Bearer 回退都会受影响。网关通过 Nacos 发现它，但集中机各服务的 `TF_USER_URL` 也要改成分机地址。除非有明确理由，建议**最后再拆 user**。
- **`console` 不是 Java 服务**：不连 MySQL/Redis/Nacos，不需要身份签名密钥，也不经网关。浏览器直接访问 `http://<分机IP>:8301`；它的日志检索依赖集中机 Loki，拆出后需要单独处理（见 6.4）。
- `game` 的排行榜使用 Redis，属于硬依赖；`reader`/`music` 代码没有直接使用 Redis，但 `/actuator/health` 会检查，建议保持连通。
- `chat` 不在本文范围。它还有 WebSocket（`/ws/chat`）和 `chat-images` 卷，拆出时需额外处理，不要直接套用本文的 Java 模板。

健康检查路径：

| 服务 | 健康检查 |
|---|---|
| user | `/api/v1/user/health`、`/actuator/health` |
| reader | `/api/v1/reader/health`、`/actuator/health` |
| game | `/api/v1/game/health`、`/actuator/health` |
| music | `/api/v1/music/health`、`/actuator/health` |
| console | `/healthz` |

```text
              ┌────────────────────────────┐
```

## 3. 端口与网络矩阵

### 3.1 分机 → 集中机

| 端口 | 用途 | 适用服务 | 是否必须 |
|---|---|---|---|
| `3306`（或 `13306`） | MySQL | user / reader / game / music | 必须 |
| `6379` | Redis | user（会话）、game（排行榜）必须；reader/music 健康检查 | user/game 必须，其余建议 |
| `8848` + `9848` | Nacos 配置与注册；**9848 常被漏配** | user / reader / game / music | 必须 |
| `8101` | `tf-user`，Bearer 回退与登录校验 | 除 user 外的 Java 服务 | 建议；user 未拆时保留 |
| `443` | `ghcr.io` 拉镜像、GitHub API | 全部 | 拉镜像必须；console 可选 |
| `13100` | Loki（仅集中机回环，默认不可达） | console | 默认不可用，见 6.4 |

### 3.2 集中机 → 分机

| 端口 | 用途 | 适用服务 |
|---|---|---|
| `8101` | 网关转发 user | user |
| `8103` | 网关转发 reader | reader |
| `8104` | 网关转发 game | game |
| `8105` | 网关转发 music | music |
| `8301` | **浏览器直连 console**（来源是用户网段，不只是集中机） | console |

> 端口必须与容器内部端口一致。Java 服务端口写死在 `application.yml`（8101/8103/8104/8105），Nacos 注册的就是这个端口；如果分机宿主映射成别的端口，必须同时设置 `SPRING_CLOUD_NACOS_DISCOVERY_PORT`，否则网关会访问错端口。

### 3.3 前置连通性自测（分机执行）

```powershell
# MySQL 若直连容器发布端口，把 3306 换成 13306
Test-NetConnection 10.28.13.214 -Port 3306
Test-NetConnection 10.28.13.214 -Port 6379
Test-NetConnection 10.28.13.214 -Port 8848
Test-NetConnection 10.28.13.214 -Port 9848
Test-NetConnection 10.28.13.214 -Port 8101
```

按要拆的服务检查对应项；`user`/`game` 必须 Redis 可达。任何一项不通，先解决网络，不要开始迁移。

## 4. 我这边（集中机）需要做的事

### 4.1 选择服务与分机 IP

- 一次只拆一个服务，验证通过后再拆下一个；
- 确认分机局域网 IP（`ipconfig` 中的 `192.168.x.x` / `10.x.x.x`），并在路由器上尽量固定（DHCP 保留），否则分机 IP 变化后 Nacos 里仍是旧地址；
- 确认分机磁盘空间：`reader`/`music` 按现有卷大小预留，`console` 很小。

### 4.2 准备凭据（按服务最小化）

| 服务 | 需要分发 | 不要分发 |
|---|---|---|
| user | `FM_USER_DB_PASSWORD`、`FM_APP_NACOS_PASSWORD` | 管理员密码、迁移账号、root、身份密钥 |
| reader | `FM_READER_DB_PASSWORD`、`FM_APP_NACOS_PASSWORD`、`FM_IDENTITY_SECRET` | 迁移账号、root |
| game | `FM_GAME_DB_PASSWORD`、`FM_APP_NACOS_PASSWORD`、`FM_IDENTITY_SECRET` | 迁移账号、root |
| music | `FM_MUSIC_DB_PASSWORD`、`FM_APP_NACOS_PASSWORD`、`FM_IDENTITY_SECRET` | 迁移账号、root |
| console | 可选 `GITHUB_TOKEN`（只读）、可选 `TF_CONSOLE_LOG_TOKEN` | 数据库/Nacos/身份密钥 |

> `user` 自身关闭了统一鉴权拦截器（`fm.auth.enabled: false`），不需要 `FM_IDENTITY_SECRET`；但**其他服务**都需要，而且必须与网关一致。
> 传递方式：密码管理器、一次性加密链接或当面拷贝。不要走聊天群、邮件正文、Git 提交。不要把集中机 `.env` 整个发过去。

### 4.3 停掉集中机上的目标服务，并防止被重新拉起

以 reader 为例：

```bash
cd /path/to/tf-deploy

# 先停，不删容器；有数据卷的服务保留卷
docker compose -f docker-compose.yml -f docker-compose.services.yml stop reader
```

`console` 在 `docker-compose.yml`（不是 services 文件）：

```bash
docker compose -f docker-compose.yml stop console
```

两个容易踩的坑：

- **`auto-update.sh` 不会重启它**：脚本先 `ps -q <svc>`，服务未运行就跳过；
- **全量 `up -d` 会重启它**：以后更新其他服务时，不要用不带服务名的全量命令。

推荐给 compose 中的目标服务加 profile：

```yaml
# docker-compose.services.yml
  user:
    profiles: ["edge-user"]
  reader:
    profiles: ["edge-reader"]
  game:
    profiles: ["edge-game"]
  music:
    profiles: ["edge-music"]

# docker-compose.yml
  console:
    profiles: ["edge-console"]
```

之后：

- 默认 `up -d` 不会启动这些服务；
- 回滚时显式加 `--profile edge-reader up -d reader`；
- `docker-compose.migrate.yml` 的迁移 Job 不受影响；
- 对带 profile 的服务执行 `stop`/`ps`/`logs` 也要带 `--profile`。

这份改动按 `feature → test → master` 流程提交，不要只改生产目录。

不想改文件时，日常更新改为显式列服务（去掉已拆出的服务）：

```bash
docker compose -f docker-compose.yml -f docker-compose.services.yml up -d \
  gateway web console user chat reader music
```

### 4.4 迁移数据卷（仅 reader / music）

`user`、`game`、`console` 没有数据卷，跳过本节。

**顺序**：先停服务（4.3），再导出，保证没有写入。

```bash
cd /path/to/tf-deploy
mkdir -p backups

# reader 用 fishmatrix_reader-files；music 用 fishmatrix_music-files
docker volume inspect fishmatrix_reader-files

docker run --rm \
  -v fishmatrix_reader-files:/data:ro \
  -v "$PWD/backups":/backup \
  alpine sh -c 'tar czf /backup/reader-files-$(date +%Y%m%d-%H%M%S).tgz -C /data .'

ls -lh backups/reader-files-*.tgz
```

music 同理：

```bash
docker run --rm \
  -v fishmatrix_music-files:/data:ro \
  -v "$PWD/backups":/backup \
  alpine sh -c 'tar czf /backup/music-files-$(date +%Y%m%d-%H%M%S).tgz -C /data .'
```

把压缩包通过可信方式（内网共享、加密包+单独口令、移动盘）交给分机。私有书籍/音频属于敏感数据，不要走公共网盘公开链接。

### 4.5 把网关静态兜底指向分机（建议）

网关优先用 Nacos 发现；Nacos 不可用时才回退到 `TF_*_URL`。拆分后集中机容器名不存在，兜底地址要改。

```bash
# 在集中机 tf-deploy/.env 中按服务修改
# TF_READER_URL=http://<分机IP>:8103
# TF_GAME_URL=http://<分机IP>:8104
# TF_MUSIC_URL=http://<分机IP>:8105
# user 见 4.6，影响面更大

docker compose -f docker-compose.yml up -d --no-deps gateway
```

`console` 不经网关，没有对应变量。

### 4.6 拆 user 的额外步骤（影响全站）

`tf-user` 是身份事实来源，拆它比拆其他服务多三倍工作量：

1. **集中机所有依赖 user 的服务都要改 `TF_USER_URL`**：`gateway`、`chat`、`reader`、`game`、`music`。改成 `http://<分机IP>:8101` 后重建这些容器；否则 Bearer 直连回退会解析不到容器名。
2. **网关静态兜底 `TF_USER_URL` 同样改成分机地址**，并重启 gateway。
3. **分机的 user 要能访问集中机 Redis（会话）与 MySQL（用户/权限数据）**。
4. **明确通知影响范围**：分机 user 宕机 = 全站登录失败。分机要开机自启、固定 IP，最好接监控。
5. **不要给分机 `USER_ADMIN_PASSWORD`**：生产 `USER_ADMIN_SEED_ENABLED=false` 时不需要；管理员密码在数据库里，由登录接口校验。

### 4.7 防火墙放行

集中机（Windows 管理员 PowerShell，按实际网段调整）：

```powershell
# 分机访问集中机中间件（3306/13306 按实际调整）
New-NetFirewallRule -DisplayName "FM edge 3306" -Direction Inbound -Protocol TCP -LocalPort 3306 -RemoteAddress <分机IP> -Action Allow
New-NetFirewallRule -DisplayName "FM edge 6379" -Direction Inbound -Protocol TCP -LocalPort 6379 -RemoteAddress <分机IP> -Action Allow
New-NetFirewallRule -DisplayName "FM edge 8848" -Direction Inbound -Protocol TCP -LocalPort 8848 -RemoteAddress <分机IP> -Action Allow
New-NetFirewallRule -DisplayName "FM edge 9848" -Direction Inbound -Protocol TCP -LocalPort 9848 -RemoteAddress <分机IP> -Action Allow
New-NetFirewallRule -DisplayName "FM edge 8101" -Direction Inbound -Protocol TCP -LocalPort 8101 -RemoteAddress <分机IP> -Action Allow
```

分机侧放行集中机访问服务端口（以 reader 为例）：

```powershell
# 分机管理员 PowerShell；port 按服务替换 8101/8103/8104/8105
New-NetFirewallRule -DisplayName "FishMatrix edge 8103" -Direction Inbound -Protocol TCP -LocalPort 8103 -RemoteAddress 10.28.13.214 -Action Allow
```

`console` 特殊：来源是**用户浏览器所在的网段**，不是集中机：

```powershell
New-NetFirewallRule -DisplayName "FishMatrix console 8301" -Direction Inbound -Protocol TCP -LocalPort 8301 -RemoteAddress <用户网段，例如 10.28.13.0/24> -Action Allow
```

> 如果集中机 MySQL 通过 Windows 端口转发（3306 → 13306）暴露，确认 `netsh interface portproxy show v4tov4` 规则仍在；不确定时让分机直连 `10.28.13.214:13306`。

### 4.8 确认分机能正确注册

Spring Boot 支持用环境变量覆盖 Nacos 注册 IP，**不需要改代码，也不需要改 Nacos 共享配置**：

```text
SPRING_CLOUD_NACOS_DISCOVERY_IP=<分机IP>
```

验证方法（启动后）：Nacos 控制台 → `fm-prod` → 对应服务 → 实例 IP 应为 `<分机IP>`、端口为该服务端口、健康、metadata.version 等于版本号。

若仍是 `172.x`，备用方案：在 `deploy/nacos/prod/tf-<service>.yaml` 的 `spring.cloud.nacos.discovery` 下增加

```yaml
        ip: ${NACOS_DISCOVERY_IP:}
```

重新发布配置（`bash scripts/init-nacos.sh`），分机环境变量改用 `NACOS_DISCOVERY_IP`，再重启服务。空值时不影响其它实例。

## 5. 分机落地步骤（Java 服务：user / reader / game / music）

### 5.1 安装 Docker

- Windows 10/11：安装 Docker Desktop（WSL2 后端），确认 `docker version`、`docker compose version` 可执行；
- 首次启动允许 Docker 通过防火墙；
- 建议分配至少 2 GB 内存；`music` 上传大文件时分机磁盘要留足空间。

### 5.2 建目录

```powershell
mkdir D:\fishmatrix-edge
cd D:\fishmatrix-edge
```

目录中只有三个文件：

```text
D:\fishmatrix-edge\
├── docker-compose.edge.yml
├── .env
└── <volume>-2026xxxx-xxxxxx.tgz    # 仅 reader/music
```

`.env` 不要放 OneDrive、共享盘或 Git。

### 5.3 `docker-compose.edge.yml`（Java 通用模板）

同一台分机只跑一个服务时直接使用；跑多个服务时，把 `app` 条目复制成多个（`app`、`app2`…），分别设置容器名、端口和卷。

```yaml
# 分机专用：只运行一个 Java 业务服务，数据与配置全部连集中机
name: fishmatrix-edge

services:
  app:
    # 固定版本，禁止 latest：跨机自动升级会和数据库迁移节奏脱节
    image: ${SERVICE_IMAGE:?请在 .env 设置 SERVICE_IMAGE}
    container_name: fm-${SERVICE_NAME:?请在 .env 设置 SERVICE_NAME}
    restart: unless-stopped
    environment:
      TZ: Asia/Shanghai
      # 激活 Nacos 配置：tf-<service>.yaml（group=FM，namespace=fm-prod）
      SPRING_PROFILES_ACTIVE: nacos
      # 不建表、不跑 Flyway；迁移只在集中机执行
      SQL_INIT_MODE: never
      SPRING_FLYWAY_ENABLED: "false"

      APP_ENV: production
      APP_VERSION: ${SERVICE_VERSION:?请在 .env 设置 SERVICE_VERSION}
      GIT_COMMIT: ${GIT_COMMIT:-unknown}

      # ── 集中机中间件 ──
      MYSQL_HOST: ${MYSQL_HOST:?请在 .env 设置集中机地址}
      MYSQL_PORT: ${MYSQL_PORT:-3306}
      MYSQL_DB: ${SERVICE_DB:?}
      MYSQL_APP_USER: ${SERVICE_DB_USER:?}
      MYSQL_APP_PASSWORD: ${SERVICE_DB_PASSWORD:?}
      REDIS_HOST: ${REDIS_HOST:?请在 .env 设置集中机地址}
      REDIS_PORT: ${REDIS_PORT:-6379}
      REDIS_DATABASE: "0"
      NACOS_ADDR: ${NACOS_ADDR:?请在 .env 设置集中机地址}
      NACOS_NAMESPACE: fm-prod
      NACOS_USERNAME: ${FM_APP_NACOS_USERNAME:-fm-app-rw-prod}
      NACOS_PASSWORD: ${FM_APP_NACOS_PASSWORD:?}

      # ── 关键：注册到 Nacos 的必须是分机局域网 IP ──
      SPRING_CLOUD_NACOS_DISCOVERY_IP: ${EDGE_HOST_IP:?请在 .env 设置分机局域网 IP}

      # 与集中机网关完全一致的 HMAC 密钥；user 服务会忽略它
      FM_IDENTITY_SECRET: ${FM_IDENTITY_SECRET:-}
      # Bearer 直连回退；user 服务自身不需要
      TF_USER_URL: ${TF_USER_URL:-http://10.28.13.214:8101}

      # 文件落本机命名卷；user/game 不用，保留也无害
      FM_STORAGE_ENABLED: "true"
      FM_STORAGE_BASE_DIR: /app/data/files

    # reader / music 保留；user / game 删除下面两行和文件末尾的 volumes 段
    volumes:
      - app-files:/app/data/files

    # 宿主端口必须等于服务内部端口（user 8101 / reader 8103 / game 8104 / music 8105）
    ports:
      - "${SERVICE_PORT:?}:${SERVICE_PORT:?}"

    logging:
      driver: json-file
      options:
        max-size: "50m"
        max-file: "5"

volumes:
  app-files:
    name: ${SERVICE_VOLUME_NAME}
```

> `SERVICE_NAME` 只用于容器名 `fm-<name>`，需要与 `SERVICE_PORT` 对应，避免混淆。
> **`user` / `game` 没有数据卷**：必须删除模板中的 `volumes:` 挂载行、文件末尾的 `volumes:` 段，并清空 `.env` 的 `SERVICE_VOLUME_NAME`；否则 compose 会尝试创建空名卷而报错。
> 如果分机宿主端口被占用，不能只改 `SERVICE_PORT`：还要设置 `SPRING_CLOUD_NACOS_DISCOVERY_PORT=<新端口>`，或干脆换一台机器。

### 5.4 `.env` 模板

```dotenv
# ── 本服务 ──
# user   : tf-user:v0.1.11    / 8101 / fm_user   / fm_user_app
# reader : tf-reader:v0.1.12  / 8103 / fm_reader / fm_reader_app
# game   : tf-game:v0.1.13    / 8104 / fm_game   / fm_game_app
```

## 6. console 的特殊落地步骤

### 6.1 为什么单独讲

`tf-console` 是 Go 单体（前端内嵌），不连 MySQL/Redis/Nacos，不注册服务，不经网关，**也没有身份签名密钥**。它与集中机的耦合只有两处：

- GitHub API（每个仓库的流水线状态）；`GITHUB_TOKEN` 可选，不配则降级；
- Loki 日志检索；Loki 目前只监听集中机回环 `127.0.0.1:13100`，分机默认**不可达**。

### 6.2 `docker-compose.console.yml`

```yaml
name: fishmatrix-console

services:
  console:
    image: ghcr.io/take-fish/tf-console:${CONSOLE_TAG:?请在 .env 设置 CONSOLE_TAG}
    container_name: fm-console
    restart: unless-stopped
    environment:
      TZ: Asia/Shanghai
      PORT: "8301"
      # 可选；不配则使用匿名配额并自动降频
      GITHUB_TOKEN: ${GITHUB_TOKEN:-}
      # 分机默认留空：日志检索返回 503，其余功能正常
      LOKI_URL: ${LOKI_URL:-}
      TF_CONSOLE_LOG_TOKEN: ${TF_CONSOLE_LOG_TOKEN:-}
    ports:
      - "${CONSOLE_PORT:-8301}:8301"
    logging:
      driver: json-file
      options:
        max-size: "50m"
        max-file: "5"
```

`.env`：

```dotenv
CONSOLE_TAG=v0.1.5
CONSOLE_PORT=8301
GITHUB_TOKEN=
LOKI_URL=
TF_CONSOLE_LOG_TOKEN=
```

### 6.3 启动与自检

```powershell

curl.exe -s http://127.0.0.1:8301/healthz
```

浏览器打开 `http://<分机IP>:8301/`，确认泳道页加载、GitHub 配额提示正常。

### 6.4 日志检索怎么办

分机 console 访问不到集中机 Loki（Loki 只绑定 `127.0.0.1`）。三种处理方式，按风险从低到高：

1. **留空降级（推荐先这样）**：`LOKI_URL` 不设置，`/logs` 返回 503，其余功能正常。
2. **SSH 隧道**：在分机建立到集中机的隧道，把 Loki 端口映射到分机；注意 console 运行在容器里，不能直接用 `127.0.0.1`，需要让隧道监听分机网卡并配合 `host.docker.internal`，同时用防火墙限制来源。配置复杂，建议单独评估。
3. **给 Loki 增加受控入口**：在集中机前置一个带鉴权的反代，再让分机指向它。涉及安全改造，不要直接把 Loki 暴露到局域网。

### 6.5 console 拆分后的入口变化

- 入口从 `http://10.28.13.214:8301` 变成 `http://<分机IP>:8301`；
- Web 前端首页只把 `tf-console:8301` 当装饰信息展示，不会自动跳转，因此不影响其它模块；
- console 只读且当前无鉴权，务必限制来源网段，不要暴露到公网。

以单个 Java 服务为例（console 无数据卷，跳过第 4 步）：

## 9. 后续发版流程

### 9.1 我这边：正常发版

1. 从 `origin/master` 建 feature 分支，改代码并跑测试；
2. 推 feature，合 `test`，在测试栈验证；
3. **feature → master 走 PR**（禁止 test→master）；
4. 合并 master 后，对应仓库的 Release 工作流自动：
   - 计算下一个版本（例如 `v0.1.13`）；
   - 构建并推送 `ghcr.io/take-fish/tf-<svc>:v0.1.13` 与 `:latest`；
   - 创建 GitHub Release；
   - bump tf-deploy 子模块指针。

`console` 同样是 tag + 镜像，但没有数据库迁移，流程更短。

### 9.2 我这边：数据库迁移（user / reader / music）

`game` 和 `console` 没有迁移，跳过。

```bash
cd /path/to/tf-deploy

# 1) 备份（任何 schema 变更前都必须）
bash scripts/backup-mysql.sh prod

# 2) 拉取与目标版本一致的镜像（迁移代码在镜像里）
docker pull ghcr.io/take-fish/tf-reader:v0.1.13

# 3) 显式传 tag 运行迁移 Job（user/reader/music 对应 migrate-user/migrate-reader/migrate-music）
TF_READER_TAG=v0.1.13 \
  docker compose -f docker-compose.migrate.yml run --rm migrate-reader

# 4) 检查退出码与 Flyway 输出
```

原则：

- **迁移先做、镜像后升**；迁移只做加法，保证旧版本仍能运行；
- 分机不执行迁移；
- 迁移失败时不要升级镜像，先处理报错或回滚数据库备份。

### 9.3 分机：升级服务

以 reader 为例：

```powershell
cd D:\fishmatrix-edge

# 1) 记录当前版本
Get-Content .env | Select-String 'SERVICE_(IMAGE|VERSION)'

# 2) 可选：备份数据卷（reader/music）

# 3) 同时修改 .env
# SERVICE_IMAGE=ghcr.io/take-fish/tf-reader:v0.1.13
# SERVICE_VERSION=v0.1.13

# 4) 拉取并重建
docker compose -f docker-compose.edge.yml pull
docker compose -f docker-compose.edge.yml up -d --no-deps app

# 5) 验收
docker logs --tail 100 fm-reader
curl.exe -s http://127.0.0.1:8103/api/v1/reader/health
```

再到 Nacos 确认 metadata.version 已更新，最后做一次集中机侧验收。

`console` 升级：

```powershell
# .env 改 CONSOLE_TAG=v0.1.6
docker compose -f docker-compose.console.yml pull
docker compose -f docker-compose.console.yml up -d --no-deps console
curl.exe -s http://127.0.0.1:8301/healthz
```

### 9.4 回滚

**只回滚应用（推荐）**：

```powershell
# .env 改回上一个版本（SERVICE_IMAGE / SERVICE_VERSION 或 CONSOLE_TAG）
docker compose -f docker-compose.edge.yml pull
docker compose -f docker-compose.edge.yml up -d --no-deps app
```

**回到集中机运行**：

1. 分机 `docker compose -f docker-compose.edge.yml down`；
2. 集中机 `docker compose ... --profile edge-reader up -d reader`（或移除 profile 后启动）；
3. 集中机旧卷仍在；分机运行期间新增的文件在分机卷里，需要先导出并合并回去，否则新内容 404；
4. 确认 Nacos 只剩集中机实例，再验收。

> 数据库迁移不回滚（Flyway 不做自动降级），因此新版本迁移必须向后兼容。
> `user` 的回滚会重启全站认证链路，务必选低峰期。

### 10.1 分机常用命令

```powershell

```

### 10.2 故障对照表

| 现象 | 排查方向 |
|---|---|
| 容器启动即退出 | `docker logs`；MySQL 密码/地址、Nacos 账号、`.env` 是否有空值 |
| Nacos 注册失败/超时 | `NACOS_ADDR`、8848 与 **9848** 连通性、`fm-app-rw-prod` 密码 |
| Nacos 实例 IP 是 `172.x` | `EDGE_HOST_IP` 未设置或选错网卡；按 4.8 处理 |
| 网关偶发/全部 502 | 集中机 → `<分机IP>:<端口>` 不通；分机防火墙；实例是否健康 |
| 所有 Java 请求 401 | `FM_IDENTITY_SECRET` 不一致；两台机器时间偏差超过签名 TTL（120 秒） |
| `/actuator/health` DOWN | Redis/MySQL 不可达；`/api/v1/*/health` 仍 UP 说明应用本身没问题 |
| user 拆出后全站 503/401 | 分机 user 的 Redis/MySQL、集中机各服务 `TF_USER_URL`、Nacos 实例 |
| game 排行榜报错 | Redis 不可达或 `REDIS_DATABASE` 不一致 |
| reader/music 已有内容 404 | 数据卷没迁移完整；对照文件数量 |
| music 上传失败 | 文件超过 50 MB、分机磁盘满、multipart 限制 |
| console 页面打不开 | 浏览器到分机 8301 的防火墙；`CONSOLE_PORT` 映射 |
| console `/logs` 返回 503 | `LOKI_URL` 为空或不可达，见 6.4 |
| 电脑重启后不自动恢复 | Docker Desktop 未设开机启动，或容器 `restart` 被改 |
| 分机 IP 变了 | Nacos 仍注册旧 IP；重新取 IP 并更新 `.env` 的 `EDGE_HOST_IP`，重启服务 |

### 10.3 日志与链路追踪

- 集中机 Alloy/Loki **只采集集中机 Docker 日志**，分机日志不会出现在 `/logs`；
- 排障时用分机 `docker logs`，结合网关透传的 `X-Trace-ID`/`traceparent` 两边对照；
- 需要集中检索时，再评估在分机部署 Alloy 并推到集中机（Loki 目前只监听回环，需要额外打通）。

## 11. 安全注意事项

1. **密钥最小化**：只给目标服务需要的数据库密码、Nacos 应用账号、身份密钥；绝不发 root、迁移账号、管理员密码。`console` 不需要任何数据库/Nacos 凭据。
2. **密钥不落 Git/网盘**：`.env` 只在本机；不要提交、不要放共享目录。
3. **不暴露公网**：Java 服务端口只允许集中机入站；`console` 只允许用户网段入站；集中机 MySQL/Redis/Nacos 不映射公网。
4. **Redis 当前无密码**：仅限可信内网；`user`/`game` 强依赖它，网络质量要保证。
5. **数据库账号**：各服务运行时账号只有本库 DML 权限；发现泄露立即轮换并同步集中机与分机。
6. **身份密钥轮换**：`FM_IDENTITY_SECRET` 由网关与所有 Java 服务共享，必须同时更新集中机与分机，否则大面积 401；不要只改一边。
7. **时钟同步**：两台机器都开启时间同步，签名身份头有效期 120 秒，漂移过大会随机 401。
8. **console 无鉴权**：只读但能看流水线与日志，务必限制来源地址；`GITHUB_TOKEN` 用只读权限，`TF_CONSOLE_LOG_TOKEN` 不要复用其他密码。
9. **旧卷留存**：集中机旧数据卷至少保留 7 天，确认无回滚需求后再删除。
